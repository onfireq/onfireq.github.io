## 代码文件和浏览器里的网页的关系

html文件：超文本标记语言文件，用于描述网页的结构和内容。

css文件：层叠样式表文件，用于描述网页的外观和布局。

js文件：JavaScript文件，用于描述网页的交互和动态效果。

代码是源文件，浏览器读取代码文件，按照html、css、js的顺序，将代码渲染成网页。

网页与源代码不是同一个形态，但是它们有直接的关系。

这跟互联网有什么关系呢？

如果我有非常多的信息，想要开放给更多的人看到，我就可以利用互联网网络分发出去，实现信息的共享。

假如说有一个图书过，或者是有一个非常多内容的机构，它把所有的资料都存储在一台计算机上。这个时候就可以供很多人去访问。只要这台电脑一直开着机。

这个远程的电脑，我们通常称之为服务器。服务器是互联网网络上的一个设备，它负责存储和处理数据。

访问网站 = 访问另一台电脑的内容

访问网站的流程是：

1. 用户在浏览器中输入域名或IP地址。
2. 浏览器会根据域名或IP地址，查找对应的服务器。
3. 浏览器会与服务器建立连接。
4. 浏览器会发送请求，请求服务器返回网页。
5. 服务器会返回网页，浏览器会渲染网页。
6. 用户可以在浏览器中查看网页。

我需要将信息存储在服务器上，然后通过域名、IP地址、端口、协议、数据包、网络设备等技术，将信息传递给浏览器。

```text
服务器：持续开放对外资源
```

本质上是一台联网的电脑，不过要一直开放着给别人访问。持续保持开机，尽量避免个人在上面操作。

如何去找到服务器的？--ip地址

```text
IP地址：用于标识服务器的唯一地址
127.0.0.1：本地回环地址，0.0.0.0：所有地址，10.0.0.1：默认网关地址
120.55.100.100：服务器的IP地址
```

ip地址对于机器而言非常方便，但是对于人类来说，并不好记忆。而且，现实中的网络环境是经常变的。ip地址是动态分配的，每次连接服务器时，都会分配一个新的ip地址。

为了解决这个问题，我们引入域名，用于标识服务器的名称。

```text
域名：用于标识服务器的名称
www.baidu.com：百度的域名
www.taobao.com：淘宝的域名
www.github.com：github的域名
```

有些可能不只有一个服务器或者一个ip，但是对外只暴露了一个域名。这样我们比较方便地就可以访问到所有的服务器。

搜索引擎，虽然说域名已经方便很多了，但是还是太多了，人们是记不住的，所以需要搜索引擎来帮助人们找到需要的信息。

搜索引擎：用于查找信息的工具

域名与IP地址的关系，就好像人与身份证的关系。

域名和ip之间的对应关系由域名解析服务器来维护。

```text
DNS：Domain Name System，域名系统，用于将域名转换为IP地址的服务器
```

域名解析服务器：用于将域名转换为IP地址的服务器

```text
域名解析：将域名转换为IP地址
```

域名跟ip之间的对应关系是一个全球的标准，当我们注册了一个域名的时候，我们就会在域名解析服务器上注册一个域名，将域名和ip地址对应起来。由DNS服务器来记录与维护，并且快速地把这个对应关系分发给全球互联网。

这个时候，某一个人想访问一个域名，就会先去查DNS服务器，找到对应的ip地址，然后去访问这个ip地址对应的服务器。

在访问网页的时候，并不是说找到一个服务器就可以了，这里还有一个概念，就是端口。

```text
端口：用于标识服务器的唯一地址
```

一台服务器可以提供很多个不同的web服务。
每个web服务都有一个端口号，用于标识这个服务。
我们的电脑去访问一个服务器时，还需要确认我应该连接哪一个端口。

```text
80：默认端口，用于HTTP协议
443：默认端口，用于HTTPS协议
```

不指定端口时，默认会连接80端口。
这俩不用声明。

浏览器会自动根据协议，选择对应的端口，省略掉。

在家里面放一台电脑，持续地开着机，也可以成为服务器。

家里面的设备是共享一个ip地址的。这个ip是由路由器一致对外的。外部无法通过这个ip地址来访问家里面的具体某一台设备。

即使短暂地可以连接了，ip往往也是动态变化的。

```text
url：统一资源定位符，用于标识资源的唯一地址
```

与域名的关系：

```text
url：域名 + 路径
```
