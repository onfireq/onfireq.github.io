可以。FPGA debug 最重要的不是"多加几个 ILA 信号"，而是先回答五个问题：

```text
这个信号属于哪个时钟？
什么时候更新？
更新后什么时候有效？
跨没跨时钟域？
我看到的是当前下载的那一版吗？
```

只要这五件事清楚，大部分问题都能快速缩小范围。

## 一、FPGA debug 的基本流程

推荐固定按照这个顺序排查：

```text
需求和时序图
→ RTL仿真
→ 综合警告
→ CDC检查
→ 实现后时序
→ ILA在线观察
→ 示波器检查板外信号
```

不要一开始就盯着 ILA 猜。

### 1. 先写清楚预期时序

例如你的测量模块：

```text
tx_mark：DAC周期起点，1拍
tx_high_mark：DAC高电平完整区间
ADC：经过模拟链路后变化
edge_det：ADC穿越阈值，1拍
tx_ts：发送起点时间戳
rx_ts：接收边沿时间戳
delay：rx_ts-tx_ts
```

然后写出必须成立的关系：

```text
tx_mark发生
→ tx_ts更新
→ tx_high_mark进入有效状态
→ ADC响应
→ edge_det发生
→ rx_ts更新
→ delay更新
```

如果 ILA 中违反这个顺序，就从第一次违反的位置查。

## 二、每个信号都要建立"身份证"

建议对关键寄存器记录五项信息：

```text
名称：
时钟域：
复位值：
单位：
更新条件：
有效条件：
```

例如：

```text
pulse_tick
时钟域：clk_125m
单位：8 ns/计数
复位值：32'hFFFF_FFFF
更新条件：debug_enable=1
有效条件：pulse_period_cfg非0
```

再例如：

```text
adc1_data_a_d0
时钟域：adc1_clk
数据格式：12位，需确认offset binary或二进制补码
极性：当前顶层进行了按位取反
有效条件：ADC初始化完成
```

这样很容易发现：

```text
adc1_data_a_d0属于adc1_clk
测量模块却属于clk_125m
```

这就是CDC风险。
