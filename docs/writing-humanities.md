# 人文文章写作指南

历史、文化、阅读与日常观察统一放在「人文」分类，用标签标明具体主题。先围绕一个想弄明白的问题写，篇幅和章节按内容需要取舍。

## 从模板开始

### 在网站编辑器里写

1. 打开「博客 → Markdown 编辑器」，点击「人文模板」。
2. 编辑器会新建独立草稿，填写当天日期，并保留已有草稿。
3. 修改标题、摘要、标签和文件名，按需删去模板章节，再开始写正文。
4. 检查右侧预览，下载 Markdown，保存到 `content/blog/humanities/`。
5. 写完后把 `published: false` 改成 `published: true`，运行检查，再提交部署。

编辑器草稿只保存在当前浏览器；换设备前下载文件。下载和复制都不会自动发布文章。

### 在本地或 Wolai 里写

- 本地：复制 `content/templates/humanities.md` 到 `content/blog/humanities/`，给副本取一个新的文件名。保留原模板，方便下次使用。
- Wolai：沿用现有写作与同步流程。同步后检查生成的 Markdown 是否保留完整 frontmatter，并确认文件位于 `content/blog/humanities/` 或 `content/blog/人文/`。当前分类由本地文件夹决定，只有标签或 Wolai 页面名称不会自动建立分类。
- 不要给 frontmatter 新增 `category`、`references` 等字段；目前元数据有严格校验，资料来源写在正文末尾。

`content/templates/` 是模板目录，不参与文章列表、搜索、RSS 或站点地图。人文分类可以为空，未完成的草稿不会作为公开文章展示。

## 怎样取标题和标签

标题尽量包含一个具体问题或观察对象，例如「读《某书》：我如何理解其中的城市生活」，避免先给自己定下覆盖整个时代的大题目。

每篇选择 2–4 个有用的标签即可。建议从以下维度组合，不用全部填写：

| 维度 | 标签示例 |
| --- | --- |
| 主题 | 历史、文化、民俗、文学 |
| 范围 | 宋代、城市生活、地方文化 |
| 文体 | 读书笔记、随笔、观展记录 |

摘要用一两句话交代「讨论什么」和「主要发现」，避免只重复标题。发表日期使用 `YYYY-MM-DD`；手动复制模板时记得更新。

## 按文章类型取舍结构

| 你想写的文章 | 可以保留的结构 |
| --- | --- |
| 历史问题笔记 | 问题 → 时间与背景 → 材料与不同解释 → 我的理解 → 待查问题 → 参考资料 |
| 文化观察或随笔 | 具体场景 → 让我在意的细节 → 我的感受与解释 → 仍想追问的地方 |
| 读书笔记 | 为什么读 → 书中一个核心观点 → 我认同或疑惑的地方 → 延伸问题 → 书目信息 |

短文可以只写「缘起、我的理解」和实际使用的脚注。纯个人感受没有引用资料时，不必硬凑参考书目。

## 排版怎么用

- 人文分类自动采用书页样式：亮色为暖白纸面，暗色为深色纸面；标题使用系统宋体／衬线字体，正文保持适合长文的行宽和行距。
- 标题、摘要、日期和标签在 frontmatter 中填写即可。编辑器的人文预览与正式文章使用同一套排版。
- 正文以 `##` 划分章节，必要时用 `###` 添加小节；段落之间空一行，不需要手动加空格或 HTML。
- 模板里 `<!-- ... -->` 包裹的写作提示只保留在源文件中，人文阅读预览和正式文章会隐藏这些注释。
- 直接引文用 `>`；出处另起一段，但仍放在同一个引用块中，例如 `> —— 作者，《书名》，页码`。
- `> [!note]` 可以放补充思考或待查问题；`---` 是一条简短的分隔线，少量使用即可。
- 图片单独成段，后面用斜体段落写图注，例如 `*图 1 · 图片名称。来源：……*`，会自动居中并缩小字号。
- 在编辑器点击「查看排版示例」即可查看完整示例，不会替换正在写的草稿。

## 怎样记录材料与引用

- **材料记载**：说明信息来自哪里，必要时交代材料形成的年代和背景。
- **他人解释**：明确写出作者或研究者的名字，避免把一个人的解释直接写成定论。
- **我的理解**：写出判断和依据；不确定的地方直接说明，不必强行得出结论。
- **直接引文**：使用 Markdown 的 `>` 引用块，紧接着写出处；转述使用自己的话并保留来源编号。

模板使用 Markdown 脚注，正文上标与文末出处可以往返跳转。正文中的标记与文末定义使用相同的名称：

```markdown
这里是根据材料作出的转述。[^book]

这里引用了另一篇文章。[^web]

[^book]: 作者：《书名》，译者（如有），出版社，出版年份／版本，章节或页码。
[^web]: 作者或机构：《网页标题》，发表日期，[原文](https://example.com)，访问日期。
```

文末会自动生成「注释与出处」，不用重复添加同名章节。只列想推荐、正文未引用的书目时，可以另加 `## 延伸阅读`。

页码只在确实核对过的版本上填写；网页优先保留原始出处。使用配图时，在图片下方注明名称、来源及必要说明。

## 发布前快速看一遍

- 替换占位标题、摘要、标签和日期，删除未使用的提示与章节。
- 检查关键说法的出处，区分原文、转述和自己的推测。
- 预览标题层级、段落、图片与引用，检查链接是否正确。
- 确认文件位于人文目录，完成后才将 `published` 改为 `true`。
- 执行项目 README 中的发布前检查，再提交与部署。
